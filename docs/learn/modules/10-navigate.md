# Navigate Imprint

> **Outcome:** move to the correct workspace and agent, identify the current
> state, and know where to look before pressing a paid action.

## Prerequisites

- Imprint is open. No provider key is required to learn the shell.
- If the window looks clipped, maximise it once and confirm you are opening the
  current live launcher or packaged build.

## The interface map

| Region | Purpose | Do not confuse it with |
|---|---|---|
| Header workspace tabs | Select the business stage: Author, Audio + Music, Video + Ads, Social, Web, Brand Design, Brand Creator | A model family or autonomous business process |
| Tool switcher | Selects related agents inside a workspace, such as Draft/Publish | A project; switching tools does not create one |
| Project rail | Creates, searches, opens, renames, and removes saved contexts | A file browser or undo history |
| Centre canvas | The current agent's brief, actions, status, and output | A universal form; each agent has different contracts |
| Right rail | System health, routing, key readiness, limits, Cost History, Run Log, Learning Centre | Proof that an external provider or platform accepted a job |

## Walkthrough

1. Click each workspace tab and note which ones contain more than one tool.
2. Return to **Write** and switch between **Draft** and **Publish**. The page
   title and controls change; the selected project does not.
3. Open **SYSTEM**. Treat **Ready** as local readiness, not output quality.
4. Open **ROUTING**. A recommendation is guidance for the current task and
   eligible configuration; inspect the visible provider/model badges where the
   dedicated agent exposes them.
5. Open **API KEYS**. This is readiness/status, not a place to paste secrets.
6. Inspect session/daily limits, Cost History, and Run Log before a long job.
7. Use the header **Docs** for an agent's technical sheet and **Learning
   Centre** for operating lessons and cross-agent workflows.

## How to read the result

**Ready** means the local preconditions Imprint can inspect passed. **Running**
means a local worker or provider operation is active. **Blocked** should state a
missing requirement. A completed local step does not necessarily mean an
asynchronous provider upload, platform post, sale, or payment completed.

## Verification

- [ ] I can name the active workspace, agent, project, and tab.
- [ ] I know where route readiness, cost, and the exact run record appear.
- [ ] I can distinguish app state from external-provider or business outcome.

## Common failures

**The expected tool is absent:** confirm the workspace; a single-tool workspace
hides the redundant tool row.  
**A status is unclear:** preserve its exact wording and search it here.  
**Controls overlap:** confirm the current app instance, window size, and text
scale before treating it as a data/provider problem.
