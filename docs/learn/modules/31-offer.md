# Define one measurable offer

> **Outcome:** write one offer whose acquisition, fulfilment, acceptance, and
> economics can be observed without changing its meaning mid-test.

## Prerequisites

- An evidence passport for the buyer problem.
- One reachable buyer group and one acquisition channel.
- Authority/rights to produce and sell the proposed deliverable.

## Offer anatomy

```text
For [specific reachable buyer]
who has [observed problem with source/date],
deliver [quantity + format + outcome]
within [time]
for [price/price test],
including [explicit inclusions]
and excluding [scope/revision/support boundaries].
Acceptance occurs when [objective checklist + approver].
```

Define **qualified opportunity** before outreach or traffic. It may be a buyer
matching role/need/budget criteria, or a destination visit from the intended
audience. Generic impressions and mass messages are not automatically qualified.

## Walkthrough

1. Name the buyer narrowly enough to find and count.
2. Link the problem to its evidence passport; generated pain points remain
   hypotheses.
3. Define the deliverable, turnaround, revisions, support, and exclusions.
4. Choose one observable acquisition channel and intended action.
5. Write acceptance criteria for factual accuracy, format, quality, rights,
   policy, and buyer approval.
6. Set budget/time/quality/harm guardrails before generating assets.

## Worked example

Raw inputs: three independent venues report losing mobile enquiries because
their event pages are slow/confusing. The offer is one responsive event landing
page, supplied copy/images, one revision, delivered in five business days for a
fixed price. Qualified opportunity = a venue with a dated event, no adequate
mobile page, and an identified decision-maker.

Tempting wrong conclusion: “Three interviews prove a scalable website market.”

Correct next decision: present the same bounded offer to a predefined set of
qualified venues and measure replies, orders, accepted deliveries, costs, and
hours.

## Offer readiness checklist

- [ ] Buyer and qualified-opportunity rule can be applied consistently.
- [ ] Problem has source/date/evidence label.
- [ ] Deliverable, price, deadline, revisions, support, and exclusions are explicit.
- [ ] Acceptance checklist and approver are known.
- [ ] Rights, privacy, platform, safety, and public-claim gates pass.
- [ ] One primary paid/intended outcome and one quality/harm guardrail are named.

## Verification

Give the offer to another person. If they cannot tell what is delivered, what is
excluded, how approval works, and which event counts as conversion, it is not
ready for an experiment.

## Common failures

**Offer is “AI content/services”:** describe the buyer-visible accepted result.  
**Every buyer gets custom scope:** productise a narrow first version or treat
each as a different cohort.  
**Price is model advice:** label it `HYPOTHESIS` and test it; do not call it market data.
