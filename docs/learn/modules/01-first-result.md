# First verified result

> **Outcome:** create, edit, save, and verify one small Draft output in about
> fifteen minutes. This is a systems check, not an income test.

## Prerequisites

- Imprint opens and shows **Ready** or an understandable diagnostic state.
- At least one eligible provider/model appears in Draft.
- Session and daily limits are comfortable for a short text request.
- You can create a disposable project.

## Walkthrough

1. Open **Author → Book Author** and create a project named `Learning test`.
2. Set **Title**, **Author**, and **Type**. Open **Book Profile**, add a concrete
   hook and target reader, then press **Save Profile**.
3. Inspect the provider and model menus. The provider badge identifies the best
   eligible provider overall; the model badge identifies the best model inside
   the provider currently selected.
4. Choose the closest **Task** and enter one bounded Direction:

   ```text
   Draft a 150-word product description for a weekly meal-planning template
   aimed at busy university students. Include three concrete benefits and no
   unverified performance claims.
   ```

5. Press **Write** once. Read the status instead of submitting duplicates.
6. Edit at least one sentence. Check that the result follows the audience,
   length, benefits, and claims constraints.
7. Press **Save Draft**, switch away, return, and confirm the project restores.
8. Open **Cost History**. Record the route and cost state. “Unpriced” means
   unknown, not free.

## How to read the result

| Observation | What it proves |
|---|---|
| Text appeared | The selected route executed. |
| Constraints passed | The brief was specific enough for this small task. |
| Saved text returned | Project persistence works for this output. |
| Cost record exists | Imprint can connect the request to its local spend ledger. |
| A buyer might like it | Nothing yet; that is a hypothesis requiring a test. |

## Verification

- [ ] Input, output, route, cost state, and saved location are known.
- [ ] The text was reviewed and changed by a human.
- [ ] No paid request was repeated merely because the first felt slow.
- [ ] The output is not being presented as proof of demand.

## Common failures

**No eligible route:** open [Providers, models, and Best Fit](12-best-fit.md),
then [Access, permissions, and privacy](13-access-privacy.md).  
**Save did not restore:** confirm the project and use [Projects, saving, and
exports](11-projects.md).  
**Result is generic:** narrow the audience, source facts, deliverable, and
acceptance criteria before changing models.
